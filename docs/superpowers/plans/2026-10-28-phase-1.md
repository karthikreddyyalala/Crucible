# Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Coding round (Blind 75, Python in the browser), company-style interviews, safety
(abuse/slurs/injection), and consistent model behavior — delivered as one PR.

**Architecture:** Spec: `docs/superpowers/specs/2026-10-28-phase-1-design.md`. Work is split
into waves; tasks inside a wave touch disjoint files so they run as parallel sub-agents.
Every task is TDD (failing test first), commits only its own files with explicit
`git add <paths>`, conventional commit messages, no AI mentions, no trailers. Never push to
`main`; the branch is pushed and a PR opened at the end.

**Tech Stack:** FastAPI, Pydantic v2, pytest · React 18 + TS + Vite + Tailwind v4 + motion ·
Pyodide 314.0.7 (jsDelivr, in a Web Worker) · `@uiw/react-codemirror` 4.25.12 +
`@codemirror/lang-python` 6.2.1 · `@playwright/test` 1.52.0 (browsers already cached).

**Commands:** backend `cd backend && python3 -m pytest -q -p no:warnings -o addopts=""` ·
frontend `npx tsc -b --noEmit && npx vitest run` · e2e `npx playwright test` · live evals
`AWS_PROFILE=crucible python3 -m evals.run_accuracy_eval <label> <cases>` (from backend/).

## Wave 1 — foundations (4 parallel tasks)

### Task 1: Moderation (backend, pure)

**Files:** create `backend/safety/__init__.py`, `backend/safety/moderation.py`,
`backend/safety/terms.py`, `backend/tests/test_moderation.py`.

Interface:
```python
from typing import Literal
from pydantic import BaseModel

class Verdict(BaseModel):
    kind: Literal["ok", "abuse", "block"]
    reason: str = ""          # short machine reason: "slur", "sexual", "directed_insult", "threat"

def normalize(text: str) -> str: ...   # lowercase, leetspeak (@→a, 0→o, 1→i, 3→e, $→s, 4→a, 5→s, 7→t),
                                       # strip zero-width chars, collapse repeated letters (≥3 → 2),
                                       # join single letters split by spaces/dots ("f u c k" → "fuck")
def moderate(text: str) -> Verdict: ...
```
Rules: `block` = slur or sexual term (word-boundary match on normalized text, lists in
`terms.py`); `abuse` = profanity/insult DIRECTED at the listener (patterns: "fuck you",
"f off", "screw you", "you('re| are) (an? )?(idiot|stupid|moron|useless|dumb|trash|garbage)",
"shut up", insult + "bot|ai|marcus", threats "i('ll| will) (kill|hurt) you"); `ok` otherwise.
Tests (≥40 parametrized): each block term variant incl. leetspeak/spaced/repeated letters;
directed insults; MUST be ok: "damn, I forgot the base case", "this bug was a pain in the ass",
"holy shit that's fast", "assessment", "classic", "Scunthorpe", "cocktail", "analysis",
"shiitake", "therapist", "grape", "dickens", "Essex", "button", "class"; empty string; 6,000
chars of normal text runs < 50 ms.
Commit: `feat: moderate abusive and explicit input before it reaches the model`

### Task 3: Coding foundation (backend, new files only)

**Files:** create `backend/models/coding.py`, `backend/data/coding/harness.py`,
`backend/data/coding/problems/` (one JSON per problem), loader functions in
`backend/models/coding.py`, `backend/tests/test_coding_problems.py`.

Problem schema (Pydantic, camelCase aliases, frozen):
```python
class CodingExample(_Frozen):  input: str; output: str; explanation: str = ""
class CodingTest(_Frozen):     args: list; expected: object
class CodingProblem(_Frozen):
    id: str                      # "code-two-sum"
    title: str
    difficulty: Literal["easy", "medium", "hard"]
    topics: tuple[str, ...]
    asked: Literal["very_common", "common"] = "very_common"
    statement: str
    function_name: str
    signature: str
    starter_code: str
    examples: tuple[CodingExample, ...]           # 2–3
    visible_test_count: int                       # first N tests are visible
    tests: tuple[CodingTest, ...]                 # 10–15
    compare: Literal["exact", "unordered", "unordered_nested", "float", "custom"] = "exact"
    validator: str = ""                           # name of a validator in harness.py when compare == "custom"
    adapters: dict[str, Literal["linked_list", "tree", "graph"]] = {}   # arg name → structure; "return" for output
    reference_solution: str
    target_complexity: dict[str, str]             # {"time": "O(n)", "space": "O(n)"}
    hints: tuple[str, ...]                        # 3–5
    follow_ups: tuple[str, ...]                   # 3–5, each ends with "?"
    ideal_answer_points: tuple[str, ...]
    weak_answer_signs: tuple[str, ...]
    rubric: dict[str, str]                        # keys: correctness, efficiency, code_quality, communication
    def public(self) -> dict: ...                 # everything except reference_solution, hints, follow_ups,
                                                  # ideal_answer_points, weak_answer_signs, rubric
```
Loader: `load_problems() -> dict[str, CodingProblem]` (lru_cache, globs the directory),
`find_problem(id)`, `problems_for(difficulties: set[str]) -> list[CodingProblem]`.

Harness (`harness.py`, runs unchanged in CPython and Pyodide):
```python
def run(code: str, problem: dict, only_visible: bool = False) -> list[dict]:
    """Exec candidate code in a fresh namespace (with ListNode/TreeNode/Node classes and
    typing imports available), call problem["functionName"] for each test, convert args/
    return with adapters, compare with problem["compare"], capture stdout per test (cap 2 KB),
    and return [{"index", "passed", "got", "expected", "error", "stdout", "ms"}]. A
    SyntaxError returns one result with error "SyntaxError: <msg> (line N)" and passed False.
    Never raises."""
```
Seed 3 problems now (Two Sum — easy/exact-or-unordered; Valid Parentheses — easy/exact;
Merge Two Sorted Lists — easy/linked_list adapters). Tests: schema validates; ids unique and
match filenames; for EVERY problem the reference solution passes all tests via the harness;
the starter code fails at least one test; an infinite-loop-free harness handles a
SyntaxError, a runtime error, and wrong return types without raising; `public()` excludes
the private fields; adapters round-trip linked lists and level-order trees with None.
Commit: `feat: coding problem schema, shared test harness and first problems`

### Task 6: Python runner (frontend, new files + deps)

**Files:** `package.json` (add `@uiw/react-codemirror@4.25.12`, `@codemirror/lang-python@6.2.1`),
create `src/lib/coding/pyodide.worker.ts`, `src/hooks/usePythonRunner.ts`,
`src/lib/coding/types.ts`, `src/hooks/usePythonRunner.test.ts`, `vite.config.ts`
(`worker.format = "es"`).

Worker protocol:
```ts
type RunnerRequest = { type: "load" } | { type: "run"; id: number; code: string; problem: PublicProblem; onlyVisible: boolean };
type RunnerResponse =
  | { type: "loading"; progress: string } | { type: "ready" }
  | { type: "result"; id: number; results: TestResult[] }
  | { type: "fatal"; message: string };
```
Hook: `usePythonRunner()` → `{ status: "idle"|"loading"|"ready"|"running"|"error", run(code, problem, onlyVisible) => Promise<RunOutcome>, retry() }`,
`RunOutcome = { kind: "results"; results } | { kind: "timeout" } | { kind: "error"; message }`.
5 s timeout → `worker.terminate()`, new worker, status back to loading→ready, outcome timeout.
Harness imported via `import harness from "../../../backend/data/coding/harness.py?raw"`.
Unit tests with a fake Worker: loading → ready, run resolves results, timeout terminates and
recreates, fatal → error + retry works, concurrent run rejected while running.
Commit: `feat: run Python in a browser worker with a hard timeout`
